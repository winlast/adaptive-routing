# Стенд одной командой

Полный стенд в контейнерах: внешний сервис, два движка, маршрутизатор и
живая демонстрация. Кроме Docker, ставить ничего не нужно — ни Python,
ни зависимостей.

```bash
docker/run.sh          # собрать и запустить
docker/run.sh stop     # остановить и убрать
```

Затем открыть **http://127.0.0.1:8400**.

## Что внутри

| контейнер | что делает |
|---|---|
| `ll-stub` | внешний сервис за сетью — ввод-вывод настоящий, а не `sleep` |
| `ll-sync` | синхронный движок, запросы расходятся по потокам |
| `ll-async` | асинхронный движок, один цикл событий |
| `ll-demo` | демонстрация; маршрутизатор она поднимает сама рядом с собой |

Маршрутизатор не выделен в отдельный контейнер намеренно: переключение
режима в демонстрации — это перезапуск шлюза с другой политикой, и
отдельный контейнер пришлось бы давать демонстрации право перезапускать.

Образ собирается без `torch`, `pandas` и `scikit-learn`: оценки стоимости
уже настроены и лежат в `data/`, а обучение в работающем стенде не
нужно. Из-за этого образ меньше примерно на два гигабайта.

## Что показывает демонстрация

Идёт поток лёгких обращений, их время рисуется на графике. Кнопка
включает смешанный поток — тот же, на котором получены числа в статьях.
Переключатель меняет режим маршрутизации, шлюз поднимается заново.

Доля лёгких запросов медленнее 200 мс, измерено в этих контейнерах:

| режим | доля подтормаживающих |
|---|---|
| всё в асинхронный движок | **56 %** |
| по числу соединений (как обычный балансировщик) | 18 % |
| по оценке стоимости запроса | **4 %** |

**Это не те же числа, что в статьях** (89 %, 44 %, 7 % — а без контейнеров
на этой же машине 86 %, 38 %, 7 %). В контейнерах каждое обращение
проходит через сетевой мост Docker, и это добавляет постоянную задержку;
кроме того, на машине в этот момент работали контейнеры соседнего
стенда. Порядок и соотношение режимов сохраняются, абсолютные значения —
нет. Точные числа статей воспроизводятся командами из корневого
[README](../README.md), без Docker.

## Переменные окружения

| переменная | назначение |
|---|---|
| `POLICY` | режим шлюза при запуске (по умолчанию `budget_power_30`) |
| `BIND_HOST` | интерфейс, который слушают службы (в образе `0.0.0.0`) |
| `SYNC_URL`, `ASYNC_URL`, `STUB_URL` | адреса соседей |
