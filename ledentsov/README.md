# Премия Леденцова — материалы стартапа

Отдельная ветка проекта: превращение технического прототипа адаптивной маршрутизации в бизнес-питч для премии Леденцова. Не пересекается с материалами конференций «Русский инженер» / ИИАСУ (они зафиксированы в `docs/` и отмечены тегом `conference-ready` в git — см. `git show conference-ready` для возврата к тому состоянию).

Статус на 17.09.2026: продукт формально ещё не готов, зафиксированы только направление и черновик описания. Презентация под премию не начата.

## Название проекта

**«Интеллектуальная система адаптивной балансировки нагрузки для микросервисных и гибридных веб-архитектур»**

Выбрано из 5 вариантов как самое широкое позиционирование — не привязано к конкретному прототипу (Flask/FastAPI), оставляет пространство для роста в полноценную платформу.

## Описание для заявки (черновик)

Современная инфраструктура компаний — это десятки микросервисов, гибридные стеки из синхронных и асинхронных технологий, облачные кластеры с непредсказуемой смешанной нагрузкой. Стандартные балансировщики нагрузки (nginx, HAProxy, Kubernetes Service) распределяют трафик вслепую — по round-robin или по загрузке — совершенно не понимая, что за запрос перед ними: лёгкий он или тяжёлый, I/O-bound или CPU-bound. Из-за этого случаются каскадные просадки производительности, которые сегодня решают вручную — через изоляцию сервисов, over-provisioning и постоянный мониторинг, что дорого и не масштабируется.

Мы создаём интеллектуальный слой маршрутизации нового поколения — систему, которая учится на реальном трафике распознавать природу каждого запроса и в реальном времени (< 2 мс) направлять его туда, где он будет обработан максимально эффективно, вместо статичных правил. Ядро технологии — лёгкий обучаемый классификатор, который может встраиваться в любой существующий стек: как прослойка перед микросервисами, как плагин к API-шлюзу или service mesh, как компонент оркестрации в Kubernetes.

Гипотеза уже подтверждена на рабочем прототипе: на смешанной нагрузке между синхронным и асинхронным движками система даёт +39–87% к пропускной способности и снижает задержку в 1,8–6,1 раза относительно лучшего одиночного обработчика — без единой строчки ручных правил маршрутизации.

Дальше — расширение классификатора за пределы двух движков: интеллектуальное распределение между произвольным числом воркеров, GPU/CPU-инференс-пулами, очередями разного приоритета — то есть превращение точечного механизма в универсальный слой управления трафиком для любой распределённой системы. Рынок — каждая компания, которая перешла на микросервисы и столкнулась с тем, что классические балансировщики больше не справляются с сложностью современных нагрузок.

- Модель монетизации (SaaS-прокси / SDK с pro-версией / консалтинг+внедрение)
- Что показываем как MVP на защите премии
- Собственно презентация (дизайн, слайды)
