# LoadLens

<sub>[English version](README.en.md) — сокращённый перевод; основной
документ этот.</sub>

**Балансировщик не знает, во что ему обойдётся запрос, который он
распределяет. Мы научились это предсказывать — из обычного журнала, не
трогая ваш код.**

---

## Проблема, которую не видно

Обращения к одному и тому же адресу различаются по стоимости в десятки
раз. Вот **чужая** база данных — PostgreSQL с таблицей на 300 000 строк
за PostgREST, нашего кода в ней нет:

| запрос — **адрес один и тот же** | медиана |
|---|---|
| `/orders?id=eq.500` | 1,7 мс |
| `/orders?limit=5` | 2,0 мс |
| `/orders?limit=20000` | 49,1 мс |
| `/orders?order=amount.desc&limit=20000` | **123,1 мс** |

Разница в **72 раза**. Балансировщик видит строку `/orders` и считает
все четыре обращения одинаковыми.

**Настройкой это не лечится.** Веса в nginx задаются на маршрут, а
различие лежит внутри маршрута. Настраивать нечего.

Расплачивается за это пользователь: его быстрый запрос стоит в очереди
за чужой тяжёлой работой. На асинхронных движках — Node.js, FastAPI,
Python asyncio — одно вычисление останавливает обработку **всех**
остальных запросов: измерено, что то же обращение задерживает соседей
на 9 мс в потоковом сервере и на 125 мс в цикле событий.

## Насколько это распространено

Проверено на производственной трассе Azure Functions, опубликованной
Microsoft Research: **32 968 функций настоящих клиентов, 1,8 млрд
вызовов.**

| разброс времени внутри одного обработчика | доля обработчиков |
|---|---|
| не меньше чем в 10 раз | **44,6 %** |
| не меньше чем в 100 раз | 11,7 % |

Типичный обработчик расходится **в 8 раз** — не в 61, как на нашем
стенде с намеренно тяжёлыми операциями. Мы не выдаём одно за другое.

## Что делает продукт

### 1. Диагностика — показывает, есть ли проблема у вас

Читает обычный журнал nginx. Ничего не ставится в путь запроса, код
сервиса не меняется, зависимостей нет.

```bash
python3 loadlens/loadlens.py /var/log/nginx/access.log --html отчёт.html
```

**Или прямо в браузере, без установки:**
[loadlens/web/index.html](loadlens/web/index.html) открывается двойным
щелчком и принимает журнал перетаскиванием. Журнал никуда не
отправляется — у страницы нет сервера, отправлять некуда.

На чужом PostgREST инструмент, ничего не зная об устройстве сервиса,
сам определил из одних времён ответа, что дороже всего обходится
**сортировка** — примерно в 11 раз, тогда как число строк влияет
заметно слабее.

**В рублях, а не в процентах.** Назовите счёт за серверы этого сервиса —
и отчёт покажет, во что обходится каждый маршрут:

```bash
python3 loadlens/loadlens.py access.log --bill 150000
```

В браузере то же самое делает поле «₽ в месяц» под отчётом. Счёт
распределяется пропорционально времени обработки; допущение здесь одно
и названо прямо в отчёте: счёт растёт пропорционально этому времени.
Это разбор сегодняшних расходов, **не обещание экономии** — сколько
удастся сберечь, журнал показать не может.

### 2. Маршрутизатор — чинит проблему там, где она есть

Оценивает стоимость запроса **до** обработки и не пускает тяжёлые
обращения в цикл событий, где они блокируют всех остальных.

Три формы поставки, одна и та же политика:

| форма | кому |
|---|---|
| [`nginx/`](nginx/) — модуль на Lua | у кого уже стоит nginx: три файла, пересборка не нужна |
| [`gorouter/`](gorouter/) — один двоичный файл | у кого nginx нет |
| [`docker/`](docker/) — весь стенд одной командой | чтобы посмотреть, как это работает |

## Что это даёт в числах

Один и тот же nginx, тот же трафик, те же обработчики. Отличается только
способ выбора узла.

| | обычный `least_conn` | LoadLens |
|---|---|---|
| лёгкие запросы, медиана | 103,9 мс | **11,3 мс** |
| лёгкие запросы, p95 | 852,4 мс | **73,0 мс** |
| доля медленнее 200 мс | 36,9 % | **0,0 %** |

Главное здесь — не отдельные числа, а поведение под нагрузкой:

| одновременных потоков | `least_conn`, p95 | LoadLens, p95 |
|---|---|---|
| 2 | 83 мс | 70 мс |
| 8 | 233 мс | 71 мс |
| 16 | 544 мс | 72 мс |
| 32 | **998 мс** | **80 мс** |

**У обычной балансировки задержка растёт в двенадцать раз. У нас не
растёт.**

Отсюда деньги. При обещании «p95 не хуже 100 мс» система держит **59,2
запроса в секунду против 37,8** — на 57 % больше. Для сервиса на 1000
запросов в секунду это 17 экземпляров вместо 27: **экономия 656 640 ₽ в
год** по публичному прейскуранту Yandex Cloud. Расчёт —
[ЭКОНОМИКА.md](ЭКОНОМИКА.md).

Сам маршрутизатор стоит **58 наносекунд на решение** (замер на Go, без
единого выделения памяти) — около одной десятой процента ядра при тысяче
запросов в секунду.

## Где это не работает

Границы измерены, а не замолчаны. Это часть продукта, а не оговорка
мелким шрифтом.

- **При мягком обещании по отклику пользы нет.** При p95 ≤ 200 мс
  экономия — ровно ноль рублей. Пакетной обработке, выгрузкам и очередям
  задач продукт не нужен, и мы не будем его туда продавать.
- **Пропускная способность падает на 21 %.** Это размен: тяжёлые
  обращения уходят туда, где идут медленнее, зато лёгкие перестают за
  ними стоять.
- **На однородном потоке маршрутизация вредна**, а не бесполезна: на
  чистом вводе-выводе проигрывает асинхронному движку 43 %.
- **При деградации самого охраняемого движка преимущество теряется.**
  Подход опирается на то, что движок остаётся таким, каким его измерили.
- **Боевого трафика настоящей компании мы не видели.** Это главный
  пробел, и именно поэтому первый шаг — бесплатная диагностика, которая
  ничего не меняет в чужой системе.

## Проверьте сами за десять минут

[ПРОВЕРЬ_САМ.md](ПРОВЕРЬ_САМ.md) — четыре проверки, каждая одной
командой: потрогать разброс руками на чужом сервере, увидеть, как
инструмент находит его сам, посмотреть живую демонстрацию и сверить
посылку с производственной трассой Microsoft.

Правило проекта: **ни одно число не попадает в текст, пока не лежит в
файле в `data/`.** Соответствие проверяется командой
`python3 tools/verify_numbers.py` — 64 утверждения.

## Структура

| путь | содержимое |
|---|---|
| `loadlens/` | диагностика: читает журнал и показывает проблему |
| `loadlens/web/` | она же в браузере, одним файлом, без сервера |
| `nginx/` | маршрутизация модулем внутри nginx |
| `gorouter/` | маршрутизатор отдельной программой на Go |
| `docker/` | весь стенд одной командой |
| `demo/` | живая демонстрация эффекта в браузере |
| `gateway.py`, `core/`, `workers/` | стенд, на котором всё измерялось |
| `experiments/`, `data/`, `figures/` | замеры и их результаты |
| `thirdparty/` | проверки на чужом ПО и на трассе Azure |
| `tools/` | сборка страницы и сверка чисел с данными |

Отрицательные результаты и границы применимости собраны выше, в
разделе «Где это не работает». Методика замеров — в коде экспериментов,
все исходные величины — в `data/`.
